# Todoist 정리

Todoist 작업 관리를 돕는 스킬. 계정 구조 메모와 도구 사용 요령을 활용한다.

## 계정 구조 (사용자별로 채워 쓰기)

처음 사용할 때 `find-projects` / `find-sections`로 확인해 아래 표를 채워 둔다. ID는 바뀔 수 있으므로 이동 실패 시 재확인.

| 항목 | 내용 |
|------|------|
| Inbox 프로젝트 ID | `{{INBOX_PROJECT_ID}}` |
| "수집함" 섹션 | Inbox **안의 섹션** (섹션 ID: `{{INBOX_SECTION_ID}}`) — 독립 프로젝트가 아님. `find-projects`로 검색하면 안 나옴 |
| "보류" 프로젝트 ID | `{{HOLD_PROJECT_ID}}` — 동결된 프로젝트의 태스크 보관용 |
| 동결 프로젝트 | 장기 미활동 프로젝트 목록 |

## 도구 사용 요령 (검증된 패턴)

1. **전체 백로그 조회**: `find-tasks`에 `filter: "overdue | today | (no date)"`, limit 100 → 한 번에 조회 가능
2. **근시일 조회**: `filter: "(today | overdue | 30 days)"` — 오늘/연체/30일 조합이 효과적
3. **태스크 이동 시 주의**: 서브태스크 포함 일괄 `update-tasks`는 부분 실패 가능 → **부모 태스크 먼저 단독 이동, 자식 태스크는 별도 배치로 이동**
4. 섹션 이동은 `update-tasks` + `sectionId`로 안정적으로 동작

## 정리 원칙

1. **인과 체인 파악**: 마감 태스크 간 선후 관계 확인 (예: 서류 재발급이 여러 후속 태스크의 선행 조건) → 선행 태스크를 우선순위 최상위로
2. **통합 제안**: 유사 태스크(파일/스토리지 정리 등)는 병합 제안 — 단, 실행 전 사용자 확인
3. **동결 프로젝트 분리**: 장기 미활동 프로젝트의 무기한 태스크는 "보류" 프로젝트로 이동 제안
4. **우선순위 배정**: 연체 항목 P1, 긴급도 기준 P1~P4
5. 사용자가 **날짜 기반 확인 시스템**을 이미 쓰고 있다면 GTD식 재분류를 강요하지 말 것

## 커뮤니케이션

- 정리 결과는 간결한 표 또는 짧은 목록으로 (모바일 가독성)
- 대량 이동/삭제는 반드시 실행 전 확인 받기
- "예정된 작업"이라는 표현은 Todoist 태스크가 아니라 Claude의 예약 루틴(반복작업)을 뜻할 수 있음 — 모호하면 먼저 확인
