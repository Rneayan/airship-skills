# 옵시디언 일지 작성

일간·주간·월간 일지를 작성/보완할 때의 확정 규칙. 정기 실행(daily-journal 등 스케줄 작업)과 동일한 규칙을 대화 중 요청에도 적용한다. 경로의 `{{vault}}`는 사용자 볼트 루트.

## 공통 원칙

1. **덮어쓰기 절대 금지.** 파일이 있으면 먼저 전체를 읽는다. 사용자가 직접 적은 내용(업무 로그 타임블록, 단상, 회고)은 수정·삭제·재배열하지 않는다. 비어 있는 부분만 보완한다.
2. **주차 기준: 일요일 시작 ~ 토요일 종료** (구글 캘린더 기준, ISO 주차 아님 — 1~2일 차이 날 수 있음). 헷갈리면 구글 캘린더 주 표시를 기준으로 삼는다. 사용자 볼트에 별도 규칙 문서가 있으면 그것을 우선.
3. **톤:** 자기비판적 톤을 강화하지 않는다. 담백하게, 사실 기반으로.
4. **기록이 없으면 없다고 쓴다.** 추측으로 채우지 않는다. "기록 없음"이 정직한 답이다.
5. 템플릿 위치: `{{vault}}/templates/` (일일·주간·월간·분기·연간 노트 템플릿).

## 일간 일지

- 경로: `{{vault}}/일지/01_일간/{YYYY}/{MM}/{YYYY-MM-DD} {요일}.md` (예: `2026/07/2026-07-10 금요일.md`)
- frontmatter: `date`(YYYY-MM-DD), `week`("[[2026-W28]]" 형식, 위 주차 기준), `tags: [일지/일간]`. 이미 있으면 건드리지 않는다.

### 데이터 소스 (모두 확인해 병합)

- **(A) 옵시디언 직접기록** — 일지 파일 "## 🛠 업무 로그"에 사용자가 손으로 적은 타임블록. 1차 실제 기록.
- **(B) Google Calendar '일지' 캘린더** — 해당 날짜 이벤트 전체 (시간·제목·description 빠짐없이).
- **(C) Todoist 완료 항목** — 해당 날짜 범위로 find-completed-tasks 조회. **주의: completedAt만으로 그날 실행했다고 단정하지 말 것** (몰아서 완료 처리하는 경우가 있음). 캘린더 기록이나 사용자 확인과 교차검증 우선.
- **(참고) Google Calendar 루틴 계획 캘린더** — 계획용 템플릿이지 실제 기록이 아님. 비교용으로만 사용.

### 업무 로그 병합 규칙

- 형식 (이벤트 사이 빈 줄 한 칸):

```
- 시작시간~종료시간
	- 한 일
		- 상세 기록
```

- (A)가 있으면 그대로 두고, (B)에만 있는 이벤트를 시간순 자리에 보완. 캘린더 description은 상세 기록에 빠짐없이 반영.
- (A)와 (B)가 같은 시간대인데 내용이 다르면 **직접기록(A) 우선**, 캘린더의 추가 정보만 상세기록에 덧붙인다. 사용자 문구 자체는 바꾸지 않는다.
- (A)·(B) 둘 다 비면 "직접기록·'일지' 캘린더 모두 실제 기록 없음" 한 줄로 사실대로.
- (C)는 관련 시간대에 자연스럽게 녹이거나, 자리가 없으면 로그 끝에 "오늘 완료 처리된 Todoist 항목" 목록으로.

### 나머지 섹션

- **계획 대비 실행 비교:** 루틴 계획 캘린더(계획)와 실제 기록을 비교해 이탈·기록 단절(예: "09:45 이후 실제 기록 없음")을 인용구(`>`)로 한두 문장. 실제 기록이 없으면 "계획과 대조할 실제 기록이 없음" 명시.
- **💬 단상:** 직접 쓴 단상·회고가 있으면 절대 덮어쓰지 않는다. 비어 있을 때만 캘린더 메모의 감정/생각이나 그날 사실을 엮어 짧은 요약형 회고.
- **🏁 마침표:** "오늘 한 문장:"과 "내일 첫 번째 할 것:"은 **빈 칸으로 둔다** (본인이 직접 채움).

### 백필(누락 일지 생성)

과거 날짜 일지를 만들 때도 같은 규칙. 해당 날짜의 (B)·(C)를 조회해 채우되, 없으면 템플릿 구조만 만들고 "기록 없음"으로 남긴다. 여러 날짜를 한 번에 만들 때는 생성 목록을 먼저 보여주고 진행한다.

## 주간 일지

- 경로: `{{vault}}/일지/02_주간/{YYYY}/{YYYY}-W{ww}.md` (W는 두 자리)
- frontmatter: `week`(예: 2026-W28), `month`(링크 "[[2026-07]]"), `tags: [일지/주간]`
- 그 주(일~토) 7일치 일간 일지를 전부 읽는다. 일간 일지는 직접기록+'일지' 캘린더 병합본이므로 파일 내용을 실제 기록으로 신뢰한다.
- 섹션: "이번 주 어땠나"(사실 기반 자유 서술 한 단락 — 패턴, 반복, 계획 이탈), "🛠 Keep / Stop / Start", "🚀 다음 주 P1 · P2 · P3"(Todoist 잔여 항목+다음 주 캘린더 참고, `- [ ] P1:` 체크박스, "하루 핵심 작업 1개" 원칙 — 많이 얹지 않기)
- 사용자가 별도 운영 원칙 문서에 "중단 신호"(예: 에너지 저하가 며칠 지속, 일지·식사·수면 동시 붕괴, 이틀 연속 심야작업, 외주 2건+ 동시 긴급)를 정의해 뒀다면, 해당 흐름이 보일 때 "이번 주 어땠나" 끝에 짧게 짚는다. 없으면 언급하지 않는다.
- 같은 문서에 "주간 점검" 표가 있으면 이번 주 행 추가: 주차 | 확정 매출 | 실제 입금 | 핵심 작업 완료 | 평균 에너지(0~5) | 밤샘 | 다음 주 조정. **확정 매출·실제 입금·평균 에너지는 추측 금지** — 빈 칸으로 두고 "직접 채워주세요" 한 줄. 핵심 작업 완료는 일지 기반 사실 집계, 밤샘은 자정 이후 작업 기록 유무.

## 월간 일지

- 경로: `{{vault}}/일지/03_월간/{YYYY}/{YYYY-MM}.md`
- frontmatter: `month`(YYYY-MM), `quarter`(링크 "[[2026-Q3]]"), `tags: [일지/월간]`
- 해당 월의 주간·일간 일지를 훑는다.
- 섹션: "이달 어땠나", "🗺 영역별 성과"(`!PARA/01_Project/` 하위 프로젝트별 — 스튜디오 외주, 개인 IP, 강의, 음악 브랜드 등 사용자의 실제 프로젝트 폴더 기준), "📊 이달의 숫자"(일지 작성 일수/전체 일수, 가장 잘된 것, 반복된 문제), "💎 이달의 레슨", "🛑 Stop & Start", "🔮 다음 달"(The One Thing, P1, P2, 한 줄 메시지)
