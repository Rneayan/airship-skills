# 한국어 회의 → 실행 기록

거친 메모나 녹취를 예쁜 요약으로만 끝내지 않고, 다음 사람이 바로 이어갈 수 있는 **증거 있는 실행 기록**으로 바꾼다.

## 핵심 구분

- **사실**: 누가 말했는지와 관계없이 확인 가능한 현재 상태
- **논의**: 의견·아이디어·가능성
- **결정**: 회의에서 명시적으로 합의한 내용
- **약속**: 특정 주체가 하기로 확답한 내용
- **실행 항목**: 행동 + 담당 + 기한 + 완료 기준
- **미해결 질문**: 담당자·기한·범위·권한이 비어 있는 항목

`검토해 보자`, `가능할 것 같다`, `나중에`를 결정이나 약속으로 승격하지 않는다.

## 작업 흐름

1. 원문 종류, 회의명, 일시·시간대, 참석자, 작성자를 확인한다.
2. 원문을 보존하고 요약본에서 출처 시각 또는 원문 구절 위치를 참조한다.
3. 결정과 약속을 먼저 추출하고, 서로 충돌하면 둘 다 남겨 확인을 요청한다.
4. 실행 항목은 `동사로 시작하는 행동 / 담당 / 기한 / 완료 기준 / 근거`로 정리한다.
5. 담당자가 없으면 주최자에게 자동 배정하지 않고 `미배정`으로 둔다.
6. 상대 날짜(`금요일`, `다음 주`)는 회의일과 시간대를 알 때만 절대 날짜로 변환한다.
7. 배포본에는 개인정보·미공개 거래처·학생 정보·NDA 자료를 제거하거나 익명화한다.

## 옵시디언 연결

- 실행 중 프로젝트 회의는 해당 `01_Project` 안에 둔다.
- 반복 운영 회의는 해당 `02_Area`에 둔다.
- 장기 재사용할 원칙만 별도의 `03_Resource` 메모상자 노트로 추출한다.
- 관련 프로젝트 허브를 링크하고, 기존 정식 회의록이 있으면 새 복제본을 만들지 않는다.
- Todoist·캘린더·메일 후속은 먼저 변경 목록이나 초안을 제시하며, 승인 전 외부 반영하지 않는다.

## 산출 기준

- 상단: 3줄 요약, 결정, 가장 가까운 마감, 막힌 항목
- 본문: 안건별 논의, 결정 로그, 실행 항목 표, 미해결 질문, 다음 회의
- 실행 항목 없는 정보성 회의는 억지로 태스크를 만들지 않는다.
- 고객 회의는 `우리 약속`과 `상대 약속`을 분리한다.
- 한국어 템플릿은 [references/templates.md](references/templates.md)를 읽는다.
- 출처와 개량 내역은 [references/attribution.md](references/attribution.md)에 있다.
